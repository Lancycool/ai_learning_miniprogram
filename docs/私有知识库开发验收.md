## 2. 后端 TDD 记录

各模块先执行对应的失败测试，再完成实现与通过检查。下面保留开发过程的红绿记录。早期单组计数只表示当时执行结果，完整回归计数见第四节。

### 2.1 可选功能配置与启动

- 红：`python -X utf8 -m pytest tests/test_knowledge_config.py` 因缺少 `app.core.knowledge_runtime` 失败。
- 绿：`python -X utf8 -m pytest tests/test_knowledge_config.py tests/test_api.py`，16 项通过。
- 检查覆盖私有开关缺省关闭、现有百炼字段、密钥遮蔽、北京原生基址校验、依赖缺失、索引故障与原题能力分离，以及新工作协程故障不阻止旧服务启动。
- 新依赖锁定后，本机仍使用 LangChain 1.4.0、core 1.6.3 和 DeepSeek 集成 1.1.0。新增 Chroma 1.5.9、LangChain Chroma 1.1.0、community 0.4.2 与 text-splitters 1.1.3。四种 loader 导入和本地 Markdown 解析通过，调用没有使用云密钥。

### 2.2 MySQL 模型、原题模型与迁移

- 红：`python -X utf8 -m pytest tests/test_knowledge_models.py` 因缺少知识库数据模型失败；`tests/test_original_models.py` 因缺少原题校验模型失败；`tests/test_knowledge_migration.py` 的两项测试因缺少迁移文件失败。
- 绿：数据表、并发草稿版本与迁移测试 8 项通过；原题与原生成模型测试 18 项通过；迁移链与 SQL 快照测试 3 项通过。数据表与现有学习和模型回归另有 15 项通过。
- 数据测试覆盖 MySQL 归属字段、任务请求唯一性、章节偏移约束、资料版本唯一性、草稿并发覆盖拒绝、确认版本唯一性、稳定分组唯一性和 32000 字符原题存储。
- 迁移测试覆盖空库的完整升级链、重复升级、旧题库保留、完整 SQL 快照执行和有私有数据时拒绝结构降级。长字段降级不自动收窄。
- Windows 沙箱阻止了 pytest 临时目录权限操作；测试使用项目内 `backend/data/pytest-knowledge` 专用目录并在允许该操作的环境中运行。测试只修改独立 MySQL 测试库。

### 2.3 资料接口、任务工作协程和文件解析

- 红：资料接口测试因路由未实现返回 404；工作协程和解析测试分别因缺少服务模块失败。
- 绿：资料接口 17 项通过；真实四格式解析与工作协程 16 项通过；配置、文件存储与百炼适配器联合测试 29 项通过。
- 接口测试覆盖登录、分页、两个用户相同主题、越权 404、202 立即返回、五秒轮询、重复编号冲突与并发幂等。存储测试使用真实 30 MiB 边界，并检查 ZIP 解压总量、路径、宏和中断清理。
- 解析测试使用合成的中文 PDF、DOCX 表格、Markdown 和 TXT。它们检查完整正文、章节偏移、嵌套章节、加密及无文字 PDF、文字限额、子进程超时与取消。
- 工作协程测试检查并发领取、释放数据库连接、旧租约、排队超时、关闭取消、受控日志和删除后的迟到结果拒绝。实际解析与索引处理链的检查见 2.5 和 2.6。

### 2.4 百炼 HTTP 适配器

- 红：测试因缺少 `BailianEmbeddings` 失败。北京工作空间地址兼容测试也先失败。
- 绿：HTTP 替身测试 14 项通过；地址兼容并入配置测试后通过。
- 测试覆盖 LangChain 同步和异步接口、十条分批、query/document、1024 维、乱序恢复、缺项、非法及非有限数值、429/5xx 一次重试、不可重试错误、总预算和取消。测试没有调用真实百炼。
- 当前官方文档同时列出北京工作空间原生基址。系统允许该北京基址与现有北京 DashScope 基址，但不修改用户配置，也不切换地域。（Alibaba Cloud, “Embedding”）

### 2.5 处理链、RAG、原题与学习

- 红：处理服务、向量库、Agent 和原题服务测试因缺少模块或行为失败。索引重建、已确认题库列表、定位辅助、提交回滚和 Agent 搜索预算的新增测试也先失败。
- 绿：实际处理与原题审核联合测试 11 项通过；Agent、原题练习、五种题量的私有报告与私有出题任务联合测试 19 项通过；原题定位与配置测试 21 项通过；向量、解析与 Agent 联合测试 27 项通过。
- 系统已验证 5/5/2 稳定分组、五个以上选项判题、一至五题的长原题报告、逐字引用、未完成隐藏来源、重做再次隐藏、混合错题复习完成后展示，以及删除原文后保留学习快照。
- 跨进程 Chroma 检查由子进程写入并退出，主进程随后读取同一目录。另一个配置指纹下的同一文档也能在删除时清理。
- 提交失败测试发现了 SQL 回滚后访问过期用户对象的问题，也发现了提交成功但响应丢失时误删新章节正文的问题。系统已修正，两类测试已通过。清理故障与归属重试也已通过。
- 完整后端第一轮为 245 项通过、三个警告、覆盖率 88%。开发者不能把这一轮记为达到 90%，后续需要补充检查并重跑。

### 2.6 综合链路与并发修复

- 红：删除接口测试因缺少 `cleanup_task_id` 失败；原题并发测试因两个请求都创建 `normal` 练习失败。
- 绿：对应两项测试和清理故障重试测试共三项通过。系统现在返回清理编号，列表提供拥有者的最新待清理任务。MySQL 锁定读取保证并发请求只有一次首次原题练习。
- 四格式综合测试使用真实 PDF、DOCX、Markdown、TXT，执行上传 API、实际解析子进程、MySQL 保存、百炼 HTTP 适配器和真实本地 Chroma。测试只替换外部向量 HTTP 响应。测试检查章节检索范围、重开持久化目录、新版本索引、整库删除、四份资料清理，以及全部原文件和向量记录清空。
- 原题 API 综合检查完成了提取、修改、确认、题库找回、异步尾组练习、五选项判题、通关、删除与历史重开。关闭私有开关后，新资料请求被拒绝，已有快照和重做仍可使用，普通主题生成仍返回成功。
- 向量服务补充测试检查同步调用的一次重试、认证失败、连接失败、非法 JSON 和空文字。测试确认公共错误不包含请求正文与上游异常内容。

## 3. 原型与前端验证

### 3.1 正式前端自动检查

知识库管理、文档与文字上传、章节预览及修正、私有出题、原题审核和分组页面已实现。系统沿用现有熊猫和竹子视觉。前端状态测试、既有两个测试脚本与类型检查通过。微信和 H5 构建成功；H5 有两个包体积建议警告。

前端测试覆盖微信上传认证只刷新一次、原文件名、H5 multipart、取消上传、30 MiB、空章节不扩大范围、响应丢失恢复、五秒无重叠查询、账号切换、隐藏页面和迟到结果不跳转。私有分享与学习会话隔离测试也通过。

新增页面原型包含 14 个示例页面。用户已经确认按该原型接入前端。正式页面的 H5 操作结果见下一节。

浏览器检查使用编译后的正式 H5 页面、真实后端接口、独立 MySQL 测试库和合成账号。浏览器检查没有关闭登录校验，也没有修改业务数据库。测试入口由 `scripts/serve_private_knowledge_acceptance.py` 提供，只监听本机地址。

### 3.3 设备验证范围

微信上传适配器、认证刷新、文件名、取消与五秒轮询已通过自动测试，微信构建也已通过。本次环境没有完成微信开发者工具或真机的实际文件选择与上传。因此，本记录不把这些设备操作记为通过。

设备检查需要使用正式微信 AppID 和可访问的 API 地址。检查人员需要在微信开发者工具或真机完成文件选择、上传、切后台后返回、五秒查询、原题尾组通关和来源显示。真机 HTTPS 地址还需要在微信平台配置 request 与 uploadFile 合法域名。

H5 文件选择器实际检查覆盖 TXT 和 PDF。DOCX 与 Markdown 的完整上传及处理由四格式 API 集成测试验证。本次没有额外声称这两种格式已在浏览器文件选择器中逐一操作。

## 4. 真实服务与综合验收

真实服务检查只使用公开虚构资料，不输出真实密钥、完整模型题库或上游异常正文。首次 Tavily 单独检查返回 `success` 与 `context_used=true`；后续检查由真实 LangChain Agent 调用可选公开搜索工具。

| 检查 | 实际结果 |
| --- | --- |
| 百炼北京原生向量 | 1024 维；相关查询命中一条，距离为 0.3412；无关查询无命中。 |
| DeepSeek 私有 Agent 与出题 | 系统生成五题，保存八条实际引用；默认搜索调用为零。 |
| 资料不足 | 系统返回 `insufficient_material`，没有按模型记忆补题。 |
| Agent 可选 Tavily | Agent 调用一次公开工具，查询只等于已确认的 HTTP 429 公开主题；系统生成五道有私有依据的新题。 |
| 最终完整后端回归 | 262 项通过，三个警告，整体覆盖率为 **90.18%**，90% 门槛通过。 |
| 完整回归后的开关与 API 补充检查 | 原题 API 综合测试通过；应用代码没有在完整回归后再次修改。 |
| 前端检查 | `test:knowledge`、`test:quiz-tasks`、`test:web-search` 与 `typecheck` 全部通过。 |
| 双端构建 | `build:weapp` 与 `build:h5` 通过。H5 有两个包体积建议警告，构建缓存另有 NullDependency 提示。 |

完整后端命令在 `backend` 中执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest --cov=app --cov-report=term-missing --cov-report=json:data/knowledge-coverage.json --cov-fail-under=90 --tb=short --basetemp=E:/Projects/ai_learning_miniprogram/backend/data/pytest-knowledge
```

真实云服务命令为 `uv run --directory backend python scripts/check_private_knowledge_live.py`。它会消耗云服务额度。自动测试使用替身，并与真实服务检查分开。

系统已验证功能开关的开启和关闭，但开发过程没有改写用户的真实 `.env`。用户启用本机功能时，需要增加 `ENABLE_KNOWLEDGE_BASE=True` 并重启正式后端。关闭后，首页隐藏资料入口，新资料请求被拒绝，普通出题与已有学习快照仍可使用。

本次代码尚未自动提交、推送或归档。管理员需要按 [部署说明](私有知识库部署说明.md) 使用单进程服务，并同步备份 MySQL、私有文件和 Chroma。所有测试与浏览器验收服务已结束。
