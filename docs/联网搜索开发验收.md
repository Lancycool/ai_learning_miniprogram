# 联网搜索开发验收

本次变更为 `ground-quiz-generation-in-current-sources`。开发者在 2026 年 10 月 3 日完成后端、前端、MySQL 迁移和本地验收。系统使用用户已有的 `TAVILYSEARCH_API_KEY` 与 `ENABLE_WEB_SEARCH` 配置，验收过程没有输出密钥。

## 功能结果

系统在搜索成功时注入有限参考内容，在搜索失败时捕获错误并记受控日志，然后使用原 Prompt。系统关闭搜索时不初始化 Tavily，也不访问搜索服务。系统在取消、断开或全局超时后停止处理。

系统锁定 `langchain-tavily==0.2.18`。开发者通过假 HTTP 传输检查了实际发送的 topic、search_depth、max_results、time_range 和 include_domains，两个并发请求不会覆盖彼此的参数。系统为工具注入有 HTTP 时限和 Retry-After 支持的包装器。

系统为题库新增可空 `web_search_metadata_json`。MySQL 测试覆盖 success、fallback、disabled、旧记录、升降级迁移和重复升级。开发者已在当前本地数据库运行 `alembic upgrade head`，迁移版本为 `20261003_0002`。迁移没有删除题目、答案或学习记录。

系统在登录用户完成当前学习记录前隐藏参考内容与链接。系统在完成后允许查看来源，用户重做时再次隐藏来源。开发者测试了部分作答、完整作答、重做和访问其他用户记录的情况。

## 固定故障与前端检查

开发者测试了后端与请求开关组合、超时及一次重试、最终超时、预算不足、429、密钥与配额错误、5xx、连接断开、空结果、错误字典、无关资料、恶意指令、无效 URL、超长结果、日志故障、排队、熔断及探测恢复。

开发者核对了故障时的实际 Prompt 路径、工具尝试次数与题库保存。系统不会把搜索错误文字或残留参考内容传入原 Prompt。系统在搜索失败但模型成功时仍保存题库并创建学习记录。

前端请求模拟通过。关闭选项会发送 false，搜索回退不会重发整个生成请求，取消会调用 RequestTask.abort。取消发生在登录等待期间时，系统不会发出后续生成请求。首页的请求标识检查会忽略过期响应。来源组件测试确认未完成时不渲染来源，完成后可以查看并复制链接。

开发者已完成前端类型检查和微信小程序构建。此结果确认代码与产物通过检查，不代表微信真机已完成操作验收。

后端最终回归共有 100 项测试通过，覆盖率超过项目要求的 90%。前端请求与来源组件模拟、类型检查和小程序构建均通过。

## 真实主题对比

开发者使用真实 Tavily 配置和当前 DeepSeek 配置，对三个主题分别生成联网题库与关闭搜索题库。每次联网请求都取得有效资料，三次关闭请求都使用原 Prompt。以下数据来自最终来源排序与版本提示调整后的运行。

| 主题 | 联网总耗时 | 原 Prompt 总耗时 | 人工抽查 |
| --- | --- | --- | --- |
| Harness Engineering，AI 编程智能体领域 | 6.57 秒 | 4.92 秒 | 两条路径都理解为智能体运行环境与反馈实践。联网结果增加了参考来源，但个别题目把“第三代范式”或“主要性能瓶颈”等资料观点写成通用结论，用户仍需复核。 |
| LangChain 1.x 的 create_agent 与 LangGraph | 7.34 秒 | 4.67 秒 | 联网题库覆盖高层接口、底层运行时和自定义流程，资料包含官方发布说明。原链也给出了相关概念，本次样例不能证明联网一定提高正确率。 |
| Tavily Search 动态参数与 auto_parameters | 3.63 秒 | 4.49 秒 | 联网题库覆盖参数分类、深度和时间过滤。第一次抽查出现文档与锁定封装版本的参数优先级冲突。系统加强官方来源排序与版本提示后，最终样例避开了该冲突细节。应用实际参数由服务端构造与测试控制。 |

系统在以上三次联网请求中都使用 general、advanced、最多 8 个结果，没有强加时间过滤，每次工具尝试次数为 1。实际来源、有限参考内容、参数、题目和耗时保存在本地 `backend/data/web-search-acceptance.json`。Git 会忽略该目录。

开发者还演练了后端关闭搜索、请求仍要求开启的回滚场景。系统实际访问 Tavily 的次数为 0，原模型通过 `quiz_prompt_v1` 生成了五道题。记录保存在 `backend/data/web-search-rollback.json`，用户的原 `.env` 没有被修改。固定 MySQL 测试也确认关闭搜索时历史与重做仍可读取。

## 时限与使用边界

系统默认使用 55 秒后端总预算和 60 秒前端请求时限。Taro 文档说明请求的默认时限为 60000 毫秒，因此系统没有依赖尚未验证的更长微信请求。仓库没有生产网关配置，当前开发使用 FastAPI 本地直连。团队正式部署时仍需要核对外部网关与真机表现。（Taro）

系统为原模型保留默认 45 秒，因此默认搜索阶段至多有约 10 秒可用时间。搜索超时后可能没有重试预算，系统会直接回退。20 秒搜索阶段上限和一次重试是上限，系统不会为了用满上限而侵占模型时间。

搜索结果可能过时、错误或包含观点。用户只给出新术语时，查询仍可能返回同名领域或二手资料。系统提供参数限制、来源记录与清晰状态，但系统没有独立事实校验链。系统回退原 Prompt 后也保留模型已有知识的质量限制。

## 复现命令

开发者可以在 backend 目录运行以下命令。后端测试使用专用 MySQL 测试库，测试会重建该库的表。

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest --cov=app --cov-report=term --cov-fail-under=90
.venv/Scripts/python.exe -X utf8 -m scripts.smoke_web_search
.venv/Scripts/python.exe -X utf8 -m scripts.smoke_web_search --rollback-only --output data/web-search-rollback.json
```

开发者可以在 frontend 目录运行以下命令。

```powershell
pnpm test:web-search
pnpm typecheck
pnpm build:weapp
```
