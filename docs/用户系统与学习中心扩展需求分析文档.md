## 2. 本次扩展目标

当前版本已经完成“输入学习内容、生成题目、答题、生成报告、分享海报”的核心流程。

本次扩展需要增加稳定的用户身份。系统需要把每次学习行为保存到对应用户。用户可以查看自己的学习记录、成长情况和错题。用户也可以继续未完成的学习。

本次扩展需要实现以下目标：

1. 系统可以识别不同用户。
2. 用户可以查看和维护自己的头像与昵称。
3. 系统可以长期保存用户的闯关数据。
4. 用户可以查看历史闯关记录和报告。
5. 用户可以查看 XP、连续学习天数和阶段统计。
6. 用户可以查看错题，并按照计划复习错题。
7. 用户可以查看知识成长情况和月度学习报告。
8. 不同用户的数据必须完全隔离。

## 3. 用户范围

### 3.1 主要用户

主要用户是在微信中使用竹知岛进行个人学习的人。

用户需要完成以下主要任务：

1. 进入小程序并建立自己的账号身份。
2. 输入学习内容并完成闯关。
3. 离开小程序后继续上次闯关。
4. 查看过去学过的主题。
5. 查看错题和薄弱知识点。
6. 查看一段时间内的学习变化。

### 3.2 本次不包含的用户类型

本次暂不包含以下用户类型：

- 管理员
- 教师
- 企业管理员
- 班级成员
- 机构成员
- 付费会员

## 4. 需求优先级说明

本项目使用四级优先级：

- P0：用户系统可以使用的必要功能。缺少这些功能时，其他用户功能不能正确运行。
- P1：本次扩展的主要用户价值。P0 完成后应立即开发。
- P2：可以增强留存和复习效果的功能。P1 稳定后开发。
- P3：后续版本功能。本次只保留入口或数据扩展空间。

每个批次都必须通过人工验收后，才能进入下一个批次。

### 4.1 数据存储约束

本次扩展会保存用户、身份、会话、题库、题目、答题、报告、错题、复习计划和学习统计等关系型数据。

因此，本次扩展正式采用 MySQL。项目不使用 SQLite 作为开发过渡库或正式数据库。

当前开发数据库使用本机 MySQL 8.0。服务地址为 `localhost:3306`。开发环境、测试环境和生产环境需要保持相同的 MySQL 表结构。数据库结构变更必须保留版本记录，也必须支持按顺序升级。

开发阶段由开发者完成建库、建表和初始化。项目必须保存完整 SQL 建表语句。后续表结构变化也需要同步维护 SQL 和数据库迁移记录。

## 6. 第一批：用户登录与登录状态

### 6.1 批次目标

系统需要为每位微信用户建立唯一身份。用户再次进入小程序时，系统需要识别同一个用户。

### 6.2 功能需求

#### 6.2.1 首次进入

1. 用户首次进入小程序时，系统需要建立用户身份。
2. 系统需要为新用户生成默认资料。
3. 默认昵称需要避免显示微信身份标识或内部编号。
4. 默认头像需要使用竹知岛现有熊猫头像。
5. 登录失败时，系统需要说明失败原因，并提供重试操作。

#### 6.2.2 再次进入

1. 用户再次进入小程序时，系统需要恢复原有账号。
2. 用户不需要每次重复填写资料。
3. 登录状态失效时，系统需要尝试重新建立登录状态。
4. 系统不能因为登录状态失效而清空用户的服务器学习记录。

#### 6.2.3 未登录状态

1. 系统需要明确哪些功能允许未登录用户使用。
2. 系统需要明确未登录用户的数据是否保存。
3. 需要登录的功能必须给出清楚的引导。
4. 用户取消登录后，页面不能进入反复弹窗状态。

### 6.3 验收标准

1. 两个不同微信用户不能进入同一个账号。
2. 同一微信用户重新进入后，系统仍然识别为原账号。
3. 登录失败后，用户可以正常重试。
4. 登录状态失效后，系统可以恢复登录，或者引导用户重新进入。
5. 未登录用户不能读取其他用户的数据。

### 6.4 已确认规则

- 用户第一次生成题目前必须完成微信静默登录。
- 本轮不提供游客模式。
- 静默登录不单独展示登录说明页。登录失败时，当前页面展示失败原因和重试入口。

## 7. 第二批：用户基本信息

### 7.1 批次目标

用户可以查看自己的基础资料。用户可以按需设置头像和昵称。

### 7.2 功能需求

#### 7.2.1 查看资料

用户可以查看以下信息：

- 头像

- 昵称

- 当前总 XP

- 连续学习天数

- 加入竹知岛的时间

  TODO:实际微信小程序中右上角的XP经验bar是被小程序右上角按钮挡住，需要调整

#### 7.2.2 修改资料

1. 用户可以选择微信头像，也可以继续使用默认熊猫头像。
2. 用户可以填写或修改昵称。
3. 用户拒绝提供微信头像或昵称后，仍然可以使用默认资料。
4. 昵称为空、过长或不符合内容要求时，系统需要提示用户修改。
5. 修改成功后，首页和学习中心需要同步显示新资料。

#### 7.2.3 资料展示规则

1. 页面不能把 `openid`、用户编号或其他内部字段显示给用户。
2. 头像加载失败时，页面需要显示默认头像。
3. 昵称加载失败时，页面需要显示默认昵称。

### 7.3 验收标准

1. 用户可以查看自己的资料。
2. 用户可以修改头像和昵称。
3. 用户拒绝提供微信资料后，核心学习功能仍然可用。
4. 修改后的资料在重新进入小程序后仍然保留。
5. 用户不能查看或修改其他用户的资料。

### 7.4 已确认规则

- 默认昵称使用“竹岛学习者”。
- 用户可以使用微信头像选择能力设置头像。
- 本次不实现手机号绑定。
- 本次需要独立的个人资料页面。该页面需要先补充 UI 原型并确认。

## 8. 第三批：学习数据归属与保存

### 8.1 批次目标

系统需要把新产生的学习数据保存到当前用户。用户退出小程序后，学习结果不能丢失。

### 8.2 需要保存的数据

系统需要保存以下数据：

- 用户输入的学习内容
- 生成的题库
- 每道题的选项和正确答案
- 用户选择的答案
- 每道题是否答对
- 每道题的答题用时
- 闯关开始时间和完成时间
- 闯关完成状态
- 本次获得的 XP
- 本次复盘报告
- 本次错题

### 8.3 数据归属要求

1. 每组题库必须归属到创建它的用户。
2. 每次闯关必须归属到当前用户。
3. 每份报告必须对应一次真实闯关。
4. 系统需要根据保存的正确答案重新核对用户答案。
5. 前端提交的数据不能直接决定 XP、正确率和错题结果。

### 8.4 数据状态

一次闯关至少包含以下状态：

- 已生成，尚未开始
- 正在答题
- 已完成
- 生成失败
- 已放弃

### 8.5 验收标准

1. 用户完成闯关后，记录和报告可以再次打开。
2. 用户中途退出后，已保存的答题进度不会丢失。
3. 用户不能通过修改前端数据增加 XP 或改变正确率。
4. 失败的题库不能进入正式历史统计。
5. 同一次完成操作不能重复增加 XP。

### 8.6 已确认规则

- 当前设备中的旧 MVP 数据不导入用户账号。
- 用户主动退出后，系统保留已经提交的进度。用户可以继续学习，也可以把记录标记为放弃。
- 本轮不提供删除单条学习记录功能。

## 9. 第四批：闯关历史列表与详情

### 9.1 批次目标

用户可以找到过去学过的内容。用户可以重新查看题目、答案和复盘报告。

### 9.2 历史列表

历史列表需要按照时间倒序展示记录。

每条记录需要展示：

- 学习主题
- 完成时间
- 题目数量
- 答对题数
- 正确率或掌握度
- 学习用时
- 错题数量
- 当前状态

### 9.3 筛选和搜索

1. 用户可以搜索学习主题。
2. 用户可以按照时间查看记录。
3. 用户可以区分已完成和未完成记录。
4. 知识分类筛选需要在知识分类规则确认后开放。

### 9.4 历史详情

用户进入历史详情后可以查看：

- 本次题目
- 用户当时选择的答案
- 正确答案
- 题目讲解
- 本次复盘报告
- 本次获得的 XP
- 本次薄弱知识点

### 9.5 再练一次

1. 用户可以从历史详情再次练习。
2. 再次练习需要生成一条新的闯关记录。
3. 新记录不能覆盖原来的答题结果。

### 9.6 验收标准

1. 用户可以看到自己的历史记录。
2. 列表顺序和显示数据正确。
3. 搜索结果只包含当前用户的数据。
4. 用户可以打开历史报告。
5. 再练一次不会修改原记录。
6. 没有历史数据时，页面会显示明确的空状态和学习入口。

## 10. 第五批：未完成闯关与学习中心总览

### 10.1 批次目标

用户进入学习中心后，可以快速了解近期学习情况，也可以继续未完成的内容。

### 10.2 学习中心总览

页面按照 `prototypes/02-学习中心.html` 中的“学习中心总览”实现。

页面需要展示：

- 用户头像和昵称
- 连续学习天数
- 本周完成的关卡数量
- 本周获得的 XP
- 主要学习方向
- 最近一条未完成闯关
- 最近七天的学习情况
- 学习记录入口
- 知识竹林入口
- 错题本入口

### 10.3 继续学习

1. 系统需要展示最近一条可以继续的闯关。
2. 页面需要展示剩余题数和预计用时。
3. 用户点击后，需要从下一道未完成题目继续。
4. 已经提交过的答案不能因为继续学习而丢失。
5. 用户完成闯关后，这条记录不能继续显示为未完成。

### 10.4 XP 规则

1. XP 必须由真实答题结果产生。
2. 相同的完成操作不能重复增加 XP。
3. “再练一次”每道答对奖励 5 XP。同一原题库每天最多奖励一次再次练习 XP。
4. 到期错题复习每道答对奖励 10 XP。完成一组五题复习后额外奖励 10 XP。
5. 同一到期复习任务只能领取一次 XP。
6. XP 规则变化后，已有历史记录不能被错误重算。

### 10.5 连续学习规则

1. 用户当天完成至少一次有效学习后，系统记为学习一天。
2. 同一天完成多次学习，只增加当天的学习次数，不增加连续天数。
3. 用户中断一天后，连续天数重新计算。
4. 日期按照中国标准时间计算。

### 10.6 验收标准

1. 总览中的数字和历史记录一致。
2. 用户可以继续最近一次未完成闯关。
3. 用户不能重复领取同一次闯关的 XP。
4. 连续学习天数跨天计算正确。
5. 没有未完成任务时，页面不会展示虚假的继续学习内容。

## 11. 第六批：错题本与复习关卡

### 11.1 批次目标

系统需要帮助用户找到薄弱知识点。系统需要在合适的时间引导用户复习。

### 11.2 错题本

错题本需要展示：

- 当前错题总数
- 本周减少的错题数量
- 当前到期的复习题数量
- 错题所属主题
- 错题题干
- 历史错误次数
- 下次建议复习时间

### 11.3 错题规则

1. 用户首次答错后，题目进入错题本。
2. 用户再次答错后，错误次数增加。
3. 用户复习答对后，题目不会立即永久删除。
4. 用户连续达到规定的复习结果后，题目才会标记为已掌握。
5. 已掌握的题目需要保留历史结果，但默认不显示在待复习列表中。

### 11.4 复习关卡

复习关卡按照原型中的“旧识重温宝藏关”实现。

1. 系统需要优先选择已经到复习时间的错题。
2. 系统需要展示题目数量、预计用时和奖励。
3. 用户完成复习后，系统需要更新错题状态。
4. 复习结果需要进入学习统计。

### 11.5 验收标准

1. 普通闯关答错后，错题会进入错题本。
2. 错误次数和复习时间显示正确。
3. 复习关卡只包含当前用户的题目。
4. 用户完成复习后，错题状态会正确变化。
5. 没有错题时，页面会展示明确的空状态。

### 11.6 已确认规则

- 复习时间采用 1、3、7、14、30 天的固定间隔。
- 用户完成第五阶段并答对后，错题标记为已掌握。
- 复习关卡按照本文件第 10.4 节的规则奖励 XP。
- 本次不实现“今晚提醒我”和微信订阅消息。

## 12. 第七批：知识竹林与月度报告

### 12.1 批次目标

系统需要把分散的学习记录整理成长期成长视图。

### 12.2 知识竹林

知识竹林按照原型中的页面结构实现。

页面需要展示：

- 知识领域
- 已学习的知识点数量
- 当前领域掌握度
- 已完成节点
- 当前学习节点
- 尚未解锁节点

### 12.3 知识点状态

知识点至少包含以下状态：

- 未学习
- 正在学习
- 建议复习
- 已掌握

### 12.4 月度学习报告

月度报告需要展示：

- 本月完成关卡数量
- 平均正确率
- 总学习时长
- 各知识领域的学习分布
- 各知识领域的掌握情况
- 与上月的变化
- 下月学习建议

### 12.5 验收标准

1. 知识竹林的数据来自真实学习记录。
2. 月度报告中的数字可以从历史记录核对。
3. 没有足够数据时，系统不能编造学习结论。
4. 用户只能查看自己的知识竹林和月报。
5. 月份切换后，历史月报仍然可以查看。

### 12.6 已确认规则

- 知识领域由系统自动分类。无法稳定分类的内容进入“其他”。
- 初始知识领域包括人工智能、自然科学、经济常识、历史文化、语言学习、生活常识和其他。
- 领域掌握度由答题正确情况和错题复习阶段共同计算。具体公式以方案设计文档为准。
- 当前节点掌握度达到 60% 后，系统解锁下一个节点。掌握度达到 80% 后，节点标记为已掌握。
- 月度报告数字由数据库计算。AI 只根据真实统计结果生成文字建议。
- 本次不实现月度报告图片分享。

## 13. 第八批：账号设置与数据管理

### 13.1 批次目标

用户可以管理登录状态和自己的数据。

### 13.2 功能需求

建议包含以下功能：

- 查看个人资料
- 修改头像和昵称
- 退出登录
- 查看隐私说明
- 查看数据使用说明
- 清除本机缓存

### 13.3 退出登录

1. 退出登录不能删除服务器学习记录。
2. 退出登录后，系统不能继续展示上一位用户的数据。
3. 用户重新登录同一账号后，可以恢复原有数据。

### 13.4 验收标准

1. 用户可以正常退出登录。
2. 退出后，本机不再显示原用户的私人数据。
3. 清除本机缓存不会错误删除服务器数据。
4. 本轮不提供账号注销入口。

### 13.5 已确认规则

- 本轮不实现账号注销。
- 本轮不实现个人学习数据导出。
- 后续需要账号注销时，项目需要单独补充数据删除和保留规则。

## 14. 全局页面状态要求

所有用户相关页面都需要覆盖以下状态：

- 首次加载
- 正在加载
- 正常数据
- 空数据
- 网络失败
- 登录状态失效
- 数据加载失败
- 用户主动重试

页面提示需要说明发生了什么，也需要说明用户下一步可以做什么。

## 15. 全局数据与安全要求

1. 用户只能访问自己的资料和学习数据。
2. 系统不能相信前端提交的正确率、XP 和正确答案。
3. 系统不能在日志中记录完整登录凭证。
4. 系统不能把微信身份标识返回给普通页面展示。
5. 系统需要防止同一操作被重复提交。
6. 用户资料和学习记录需要在重新进入小程序后恢复。
7. 用户退出登录后，系统需要清理当前设备中的私人页面数据。
8. 页面需要清楚说明头像、昵称和学习数据的用途。

## 16. UI 原型约束

1. 已有页面必须严格按照现有 HTML 原型实现。

## 18. 建议的人工验收顺序

### 验收点一：用户身份

用户可以进入小程序。系统可以识别新用户和老用户。

### 验收点二：用户资料

用户可以查看和修改头像、昵称。用户拒绝提供微信资料后仍可学习。

### 验收点三：数据保存

用户完成闯关后，可以退出并重新进入。学习记录和报告仍然存在。

### 验收点四：历史记录

用户可以查看历史列表、历史详情和旧报告。

### 验收点五：继续学习

用户中途退出后，可以从正确的位置继续答题。

### 验收点六：学习统计

学习中心可以正确展示 XP、连续天数和近七天数据。

### 验收点七：错题复习

用户答错后可以在错题本看到题目，也可以完成复习关卡。

### 验收点八：长期报告

知识竹林和月度报告可以正确反映历史学习数据。

### 验收点九：账号数据

用户可以退出登录。系统不会在退出后继续展示私人数据。
