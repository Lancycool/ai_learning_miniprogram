# 私有知识库接口与使用

所有新增接口位于 `/api/v1`，需要现有登录令牌。系统对不存在和越权资源统一返回 404。系统使用独立开关 `ENABLE_KNOWLEDGE_BASE`，能力接口分别返回管理、解析、索引与原题练习的可用状态。

## 使用流程

用户在首页点击“导入自己的资料”，创建知识库，然后上传 PDF、DOCX、Markdown、TXT 或粘贴文字。系统保存资料和数据库任务后返回 202。前端在每次查询结束后等待五秒。用户离开页面后，前端暂停查询，后台继续处理。用户可以通过“恢复任务”或资料详情中的“继续查看”恢复等待。

用户可以分页查看完整正文，选择全文或章节。父章节包含范围内的子章节。用户可以修正标题、层级和正文字符范围。系统检查覆盖与交叉后创建新版本，旧任务不能发布迟到结果。界面不要求用户选择页码。

私有新题仍使用三道单选、一道多选和一道判断。系统缺省关闭私有联网。用户允许联网后，还需要单独填写并确认公开主题。Agent 才能使用固定查询的 Tavily 工具。私有正文、原题和答案不能成为搜索查询。全局关闭优先。资料不足时，系统提示补充材料。普通主题出题保留搜索失败回退原 Prompt 的逻辑。

原题导入遍历所选范围的全文，不以 RAG top-k 代替全文。系统保留原文、全部选项、答案和讲解，并按章节和题号关联末尾答案表。用户需要查看问题清单和未识别原文。用户可以编辑、补题或排除，并保存当前页。缺失或冲突答案由用户核对，AI 不能补写答案。没有讲解时，系统如实提示。填空、简答和图片题暂不支持。

用户确认后可以从资料详情找回题库。系统按版本、章节和组号固定题目身份。每组最多五题，十二题形成 5/5/2，最后一组可以只有一题。题型按原文保留。模型和向量服务不可用时，已确认原题仍可练习。用户可以从学习记录继续未完成的私有练习。

系统在整组完成后显示来源快照。重做和混合错题复习会再次隐藏来源。私有分享卡只展示通用文案和成绩。系统不会在分享卡中显示资料标题、题目和引用。资料删除后，系统清理原文件和索引，保留已经进入学习记录的题目、引用和成绩。用户可以在知识库列表查看清理进度，或点击“重试清理”处理失败任务。知识库本身被删除后，首页资料入口中的清理列表仍能找回该任务。学习报告不重新读取已删除原文。

## 接口

| 方法和路径 | 行为 |
| --- | --- |
| GET `/knowledge-bases/capabilities` | 系统返回能力、格式、限额与五秒轮询建议。 |
| GET/POST `/knowledge-bases` | 用户分页查看或创建知识库；创建返回 201。 |
| GET/PATCH/DELETE `/knowledge-bases/{id}` | 用户查看、修改或删除知识库。 |
| GET/POST `/knowledge-bases/{id}/documents` | 用户分页查看资料或上传文件；上传返回 202。 |
| POST `/knowledge-bases/{id}/text-documents` | 用户提交 `title`、`text` 和 `request_id`，系统返回 202。 |
| GET/DELETE `/knowledge-documents/{id}` | 用户查看状态或删除资料。 |
| GET `/knowledge-documents/{id}/preview` | 用户通过 `offset` 和 `limit` 查看完整正文与章节。 |
| PATCH `/knowledge-documents/{id}/chapters` | 用户提交 `version_id` 和完整章节范围，系统发布新版本任务。 |
| POST `/knowledge-documents/{id}/processing-tasks` | 用户重试解析或重建索引。 |
| GET `/knowledge-processing-tasks/{id}` | 用户查看真实阶段、数量和成功结果。 |
| GET `/knowledge-processing-tasks/cleanup` | 用户分页查看尚未完成的清理任务；`base_id` 可以限定知识库。系统只返回每份资料最新的清理任务。 |
| GET `/knowledge-processing-tasks/by-request/{request_id}` | 用户恢复上传响应丢失的任务。 |
| POST `/knowledge-processing-tasks/{id}/retry`或`/cancel` | 用户重试失败任务或取消活动任务。 |
| POST `/knowledge-documents/{id}/question-import-tasks` | 用户提交版本、章节和编号，系统提取全文原题。 |
| GET/PATCH `/question-imports/{id}` | 用户分页查看、编辑、补题和排除；`coverage_page` 返回遗漏原文。 |
| POST `/question-imports/{id}/confirm` | 用户提交 `revision`、`request_id`，系统原子确认题库，返回 201。 |
| GET `/knowledge-documents/{id}/question-banks` | 用户分页找回已确认题库。 |
| GET `/question-banks/{id}` | 用户通过多个 `chapter_ids` 查看分组，省略表示全文。 |
| POST `/question-banks/{id}/practice-tasks` | 用户提交组号、章节和编号，系统返回 202。 |
| POST/GET `/quizzes/generation-tasks`及`/{id}` | 用户沿用已有接口，私有请求增加 `knowledge_scope`。 |

上传表单包含 `file`、原始 `filename` 和 `request_id`。后端检查真实内容，不仅检查扩展名。请求编号为 16 至 64 个英文字母、数字、下划线或连字符。同编号同内容恢复原任务，同编号不同内容返回 409。草稿修改和确认需要当前版本，冲突返回 409。

任务状态为 `queued`、`running`、`succeeded`、`failed`。系统只在成功后返回 `result`，只在失败后返回受控 `error`。界面显示真实阶段与已处理数量，不伪造百分比。接口不返回密钥、私有路径、哈希或上游异常全文。

删除资料返回 `cleanup_task_id`，删除知识库返回 `cleanup_task_ids`。系统先停止新检索，再在后台清理文件和索引。旧的失败清理任务被新重试任务替代；清理完成后，任务不再出现在待清理列表。

系统缺省限制单文件 31457280 字节、每用户十个知识库、两百份资料和 300 MiB 文件量。系统还限制 PDF 五百页、正文五十万字符、索引一千片、原题一千道。原题题干和讲解各最多 32000 字符，每个选项最多 8000 字符、最多 26 个选项。系统超限后明确失败，不截断后假装完成。扫描件、加密 PDF、坏文件和图片依赖内容会得到受控失败或核对提示。
