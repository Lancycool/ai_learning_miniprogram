# 私有知识库部署说明

本期代码与本机验收已经完成。后端通过全部回归、真实云服务和本地存储检查，前端通过双端构建与 H5 操作检查。微信开发者工具和真机操作尚未验证。实际结果见 [开发验收](私有知识库开发验收.md)。

## 配置与目录

后端还会输出统一 JSON 日志，并在 `/metrics` 提供 Prometheus 指标。详细字段、抓取配置和告警建议见 [可观测性说明](可观测性说明.md)。部署者可以在 `.env` 中设置 `OBSERVABILITY_LOG_LEVEL`，默认值为 `INFO`。

后端继续读取 `backend/.env`。系统使用用户已有的 `BAILIAN_API_MODEL`、`BAILIAN_API_KEY`、`BAILIAN_API_BASE_URL`。本版使用北京原生接口基址 `https://dashscope.aliyuncs.com/api/v1` 和 `text-embedding-v4`；系统不会把它改成 OpenAI 兼容路径。密钥只保存在本机环境配置中。

系统缺省关闭 `ENABLE_KNOWLEDGE_BASE`。开发者需要在现有 `backend/.env` 中增加 `ENABLE_KNOWLEDGE_BASE=True` 并重启后端，首页才会显示资料入口。开发过程没有改写用户的真实 `.env`。系统只在启用后启动新增工作协程。向量配置错误或依赖故障不会让原有服务无法启动。资料管理和已确认原题练习使用各自依赖，百炼故障不直接阻断它们。

`KNOWLEDGE_STORAGE_DIRECTORY` 缺省为 `backend/data/knowledge`，`CHROMA_PERSIST_DIRECTORY` 缺省为 `backend/data/chroma`。相对路径以 backend 为基准，系统内部使用绝对路径。管理员需要给后端进程读写权限并预留磁盘空间。系统不能为这两个目录设置公开静态访问。默认目录已被 Git 忽略。

本版使用单机和一个后端服务进程。开发者不能通过多个 uvicorn worker 共用本机 Chroma 目录。资料解析在受限子进程中执行；它不等于多个应用服务进程。需要多服务器或应用多进程时，开发者应先调整为独立向量服务。

## 依赖与处理限额

开发者在项目根目录运行 `uv sync --directory backend --dev --locked`，即可按锁文件安装依赖。系统使用指定 LangChain loader 处理 PDF、DOCX、Markdown 和 TXT。部署者需要提前检查本地解析资源，业务请求不能自动联网下载模型、OCR 或语言资源。

系统公开单文件 30 MB 上限，其实际字节数为 31457280。系统还限制用户资料总量、解析页数、文字数、片段数、原题数量与任务时间。开发者可以在 `.env.example` 查看对应字段。系统超限后返回明确结果，不裁剪后假装处理完整。

## 数据保护、备份与回滚

管理员也可以使用百炼提供的北京工作空间原生基址 `https://<工作空间>.cn-beijing.maas.aliyuncs.com/api/v1`。系统不改变地域，不接受 OpenAI 兼容路径。

系统使用 1024 维向量，并为 Chroma 设置 cosine 距离。当前集成方法虽带有 relevance 名称，其返回值仍是距离；数值越小越相关。系统接收不大于 0.65 的结果，并复查归属、文档、版本、章节与配置指纹。系统最多返回八个去重片段。系统按章节拆分，每片最多 1000 字符，交叠 150 字符。

公开合成样本中，真实百炼对“客服核对订单和退款审批流程”的距离为 0.3412，系统返回一条片段；无关的暗物质引力透镜查询没有通过阈值。这是固定样本的依据，企业资料仍需要自己的质量检查。系统还会检查逐字引用与答案支持，资料不足不会按模型记忆出题。

地址、模型、维度和拆分版本进入配置指纹。管理员改变配置后，用户需要在资料详情点击“重新建立检索索引”。系统先写未发布索引代次，再通过 SQL 发布检查，失败时清理该代次。已解析正文独立保留，索引故障不影响原题导入。

解析子进程缺省限时 60 秒，资料任务 600 秒，私有出题总计 180 秒。Agent 规划最多 45 秒、三次模型调用和四次工具调用。原题结构定位最多四次，每次最多 15 秒；模型只能返回原文行范围。未识别内容保留在审核清单。

开发者可以运行 `uv run --directory backend python scripts/check_private_knowledge_live.py` 检查真实服务。脚本只使用公开虚构资料，不打印密钥和上游异常正文，并会消耗少量云服务额度。2026-10-04 的实际结果为 1024 维、五道私有新题、八条引用、默认搜索调用零次、资料不足错误和 Tavily 成功。

真实 Agent 的可选联网检查也已通过：Agent 使用一次固定公开主题的 Tavily 工具，并生成五道有私有资料依据的新题。用户允许联网时，Agent 可以根据资料情况选择工具；用户不允许时，Agent 没有公开搜索工具。

数据库新增迁移为 `20261004_0004` 和 `20261008_0005`。开发者从项目根目录运行 `uv run --directory backend alembic upgrade head`。新增业务表包括资料、原题和 `knowledge_retrieval_traces`、`knowledge_bad_cases`。业务 MySQL 不会被向量库替代。

系统新增可空 `quizzes.knowledge_metadata_json`、`questions.source_metadata_json` 和 `questions.original_item_id`，并把题干与讲解改为 MEDIUMTEXT。现有生成模型仍限制原来的题干、选项和题量。资料删除采用业务状态与清理任务；它不删除学习快照。

`backend/sql/004_private_knowledge.sql` 是已存在旧库的单次增量 SQL。管理员应优先使用 Alembic，不能在已有学习数据的数据库执行包含 DROP TABLE 的 `schema.sql`。完整 SQL 快照只用于空库初始化。完整升级链与该快照已经在独立 MySQL 测试库中执行验证。

百炼会接收向量化文字。DeepSeek 会接收检索片段或原题提取所需文字。Tavily 只能收到用户另行确认的公开搜索主题。系统不能在日志中保存密钥。维护追踪会保存受限长度的候选片段，用于维护者核对召回结果。部署者需要把 `KNOWLEDGE_TRACE_ADMIN_KEY` 配置为随机密钥，并把 `KNOWLEDGE_TRACE_RETENTION_DAYS` 设置为实际保留天数。维护密钥不能放入前端环境变量。

维护者查询接口为 `GET /api/v1/maintenance/knowledge-traces`，请求头为 `X-Knowledge-Trace-Key`。该接口没有用户页面，部署者需要通过内网、网关或访问控制限制来源。接口返回的追踪可能包含私有资料片段，备份和权限策略需要覆盖这两张表。系统按保留期隐藏旧记录；部署者还需要根据数据保留要求定期清理旧数据。

维护者网页位于前端 H5 的 `/pages/maintenance/index`。网页只用于维护者排查，不应加入普通用户导航。部署者需要在 H5 地址后打开该路径，并在页面中临时输入维护密钥。前端构建不需要配置 `KNOWLEDGE_TRACE_ADMIN_KEY`，也不能把该密钥写入 `TARO_APP_*` 环境变量。

管理员需要同步备份业务 MySQL、私有文件目录和 Chroma 目录。备份前，管理员应暂停新增资料任务领取，等待运行任务结束或记录中断状态。单独复制其中一个存储不能保证资料版本一致。

回滚首先设置 `ENABLE_KNOWLEDGE_BASE=False` 并重启。系统保留已存资料、题目、引用快照和成绩。数据库降级不能自动删除新功能数据或把长文本字段收窄。管理员只有在核对所需数据并完成备份后，才可以安排结构回滚。

## 本机启动与检查

开发者在项目根目录执行以下命令。后端迁移与启动使用单个服务进程。

```powershell
uv sync --directory backend --dev --locked
uv run --directory backend alembic upgrade head
uv run --directory backend uvicorn app.main:app --host 127.0.0.1 --port 8000
```

微信开发者工具需要导入 `frontend`，并使用 `pnpm build:weapp` 或 `pnpm dev:weapp` 生成的目录。真机请求需要可访问的 HTTPS API 地址。微信平台需要把这个地址配置到 request 和 uploadFile 合法域名。H5 与微信构建会写入同一个 `frontend/dist`；开发者切换平台后需要重新构建。

H5 已增加 `src/index.html`，构建会注入 `TARO_APP_API_BASE_URL`。开发者可以通过前端环境文件配置地址。`serve_private_knowledge_acceptance.py` 只用于本机隔离测试库的浏览器检查；它使用合成账号，不能作为正式部署入口。正式后端入口始终是 `app.main:app`。

本地查看 H5 页面时，开发者先执行 `pnpm build:h5`，再在 `frontend` 目录执行 `pnpm serve:h5`。开发者也可以直接执行 `python scripts/serve_h5.py --port 8765`。该命令监听 `127.0.0.1:8765`，并为 `/pages/maintenance/index` 这类直接访问路径提供 H5 回退。项目使用浏览器路径路由，维护者页面地址为 `http://127.0.0.1:8765/pages/maintenance/index`。
