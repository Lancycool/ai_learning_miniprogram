# Spec Delta

## Purpose

系统帮助用户把自己上传的题库整理成可以练习的原题记录。系统保留来源、章节、原题文字、选项与答案，并通过用户审核处理解析疑问。系统让用户按章节分组练习，同时保留现有服务端判题和学习记录能力。

## ADDED Requirements

### Requirement: 系统完整保存支持题型的原题
系统 MUST 支持单选、多选和判断原题，并保留来源题号、题干、选项、答案、来源讲解与章节。系统 MUST 不改写、概括或截断原题文字以适配现有生成限制。系统 MUST 保留原文与解析草稿的关系，并清楚列出无法导入的题型或内容。

#### Scenario: 题目超过现有生成题干长度
- **WHEN** 原题题干超过现有生成题目长度，但在原题导入的公开限制内
- **THEN** 系统完整保存与展示该题干，不截断题目

#### Scenario: 多选题有五个选项
- **WHEN** 原题有 A 至 E 五个文字选项
- **THEN** 系统保留全部选项和原答案，并允许用户在练习时选择它们

#### Scenario: 文档含填空或图片题
- **WHEN** 系统发现填空、简答、图片依赖题目或其他当前无法完整表达的内容
- **THEN** 系统在预览中列出具体问题并提示暂不支持，不把它们伪装为已成功导入

### Requirement: 导入遍历完整资料且允许核对遗漏
系统 MUST 对用户选择的完整文档或章节分批提取原题，不能只导入相似度检索返回的片段。系统 MUST 显示来源范围、已识别题目、存在问题的题目和未识别片段，提供增补或修改入口。系统 MUST 对超出处理限制的资料整体给出明确错误，不标记为完整导入成功。

#### Scenario: 题库的答案集中在文档末尾
- **WHEN** 文档前部包含题目，文档末尾包含独立答案表
- **THEN** 系统按来源题号与章节关联答案，并把重复编号或无法关联的答案列为待核对

#### Scenario: 题目跨越解析片段边界
- **WHEN** 原题题干、选项或讲解位于相邻片段
- **THEN** 系统合并完整题目或标记待核对，不重复导入或静默丢失内容

### Requirement: 用户确认后原题才进入可练习题库
系统 MUST 在导入任务完成后返回可编辑预览，而不是直接发布可练习题库。用户 MUST 可以核对和修改题干、选项、答案、章节与讲解，并补充漏识别的支持题型。系统 MUST 校验全部待发布题目，并以当前草稿版本进行幂等确认。

#### Scenario: 用户修改识别错误后确认
- **WHEN** 用户在预览中修正选项并确认有效草稿
- **THEN** 系统保存用户确认的版本，并允许按章节练习

#### Scenario: 两个页面同时修改草稿
- **WHEN** 用户基于已经过期的草稿版本提交修改或确认
- **THEN** 系统返回版本冲突，并要求用户重新读取预览

### Requirement: 系统不替原题编造缺失答案
系统 MUST 把缺少、冲突或不能匹配选项的答案标记为待处理。用户 MUST 补齐或修正所选待发布题目后才能确认。系统 MUST 不根据模型猜测填入原答案。原文没有讲解时，系统 MUST 如实提示，而不是把生成说明标成原文讲解。

#### Scenario: 原题没有答案
- **WHEN** 文档提供题目和选项，但没有答案
- **THEN** 系统保留题目草稿并提示用户补齐答案，不允许直接发布该题

#### Scenario: 原文缺少讲解
- **WHEN** 原题有有效答案，但没有讲解
- **THEN** 系统允许确认，并在学习反馈中显示原题未提供讲解

### Requirement: 原题练习按确认章节分组
系统 MUST 让用户选择已确认的原题章节，并默认按原始顺序每组使用最多五题。系统 MUST 允许剩余一至四题完成有效学习，不重复填满五题。系统 MUST 不强制原题符合生成题库的三单选、一多选、一判断比例，不调用出题模型改写原题。

#### Scenario: 所选章节只有两道有效原题
- **WHEN** 用户开始该章节原题练习
- **THEN** 系统创建两题学习记录，并允许正常答题、完成和查看报告

#### Scenario: 所选章节有十二道有效原题
- **WHEN** 用户连续创建该章节的练习分组
- **THEN** 系统按稳定分组提供五题、五题和两题，并显示分组范围

### Requirement: 原题练习保留现有学习规则
系统 MUST 在服务端判题，并复用现有完成、XP、错题、复习和历史逻辑。系统 MUST 对同一已确认原题版本与分组使用稳定题目身份，避免重新打开分组形成新的原题或绕过再次练习奖励限制。用户更新原题后，系统 MUST 不覆盖已经保存的题目、答案与成绩。

#### Scenario: 用户再次练习同一分组
- **WHEN** 用户重新练习已完成的原题分组
- **THEN** 系统使用再次练习规则，并关联原分组题目和错题身份

#### Scenario: 用户修改了原题答案
- **WHEN** 用户确认新的原题版本，而此前已有学习记录
- **THEN** 新练习使用新版本，旧学习记录保留当时的题目与答案

### Requirement: 原题管理与练习响应遵守各自权限
系统 MUST 允许当前用户在导入审核与原题管理页面查看原答案。正式练习任务和题目接口 MUST 继续隐藏未作答答案，引用内容 MUST 在整组完成后展示。系统 MUST 对所有草稿、确认题库、练习分组和引用执行用户归属检查。

#### Scenario: 用户打开原题审核预览
- **WHEN** 当前用户打开自己上传题库的审核页面
- **THEN** 系统返回用于核对的原答案，并说明这属于资料管理页面

#### Scenario: 用户查询未完成的原题练习
- **WHEN** 用户查询原题练习任务或尚未作答的题目
- **THEN** 系统不返回原答案、完整讲解和引用摘录
