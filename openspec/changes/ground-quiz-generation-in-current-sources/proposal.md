# Proposal

## Why

模型的已有知识可能缺少新概念，也可能把术语理解为其他领域。系统需要在联网可用时用搜索结果补充出题 Prompt，并在搜索不可用时保留原有出题能力。

## What Changes

- 系统使用 LangChain `langchain-tavily` 的 `TavilySearch`，把有效搜索结果作为参考资料注入原出题 Prompt。
- 系统新增后端 `enable_web_search` 配置和同名请求选项。后端关闭时不调用搜索；后端开启时，用户可以关闭本次搜索。
- 系统根据用户内容动态调整查询、搜索深度、结果数量、领域和时间范围，并限制参数值、耗时、上下文长度与调用次数。
- 系统在搜索超时、限流、密钥错误、空结果、参数处理错误或工具错误时捕获异常并记录受控日志。系统不注入搜索结果，使用原 Prompt 照常出题。
- 系统保留现有输入过滤、JSON、题量、题型与答案结构检查。搜索失败本身不返回业务错误，不阻止题库保存或学习记录创建。
- 系统保存本次是否搜索、是否实际注入资料、实际参数、来源和降级原因。系统明确区分搜索参考资料与已经核实的正确答案。
- 系统取消旧规划中的强制资料门槛、独立事实校验链、强制领域确认、材料专用模式和逐题必填引用。系统仍建议用户在输入中说明领域与版本。
- 本次同步修改两份产品文档。实施交付覆盖后端、前端、数据库迁移与测试，验收记录见 `docs/联网搜索开发验收.md`。

## Capabilities

### New Capabilities

- `quiz-knowledge-grounding`：系统提供可开关、可调参的搜索增强，并在搜索失败时使用原 Prompt 出题。
- `quiz-source-traceability`：系统记录实际搜索与 Prompt 路径、参考来源和降级原因，用户可以查看真实搜索状态。

### Modified Capabilities

无。项目尚无主规格，本次修订现有变更中的两份新增能力规格，并保留原路径。

## Impact

- 后端涉及配置、请求模型、Tavily 适配器、搜索参数策略、`QuizService`、`DeepSeekQuizGenerator` 和出题 Prompt 组合。模型继续使用 `ChatDeepSeek`。
- 两条生成接口保留现有请求与成功字段，新增可选 `enable_web_search` 及搜索元信息。登录、判题、经验值和报告接口保留原流程。
- MySQL 只需为题库增加可空搜索元信息 JSON，并同步 Alembic 与 SQL 初始化文件。系统不新增题目引用字段。
- 前端涉及本次联网开关、实际搜索状态、参考链接与降级说明。前端不需要新增强制领域确认或材料上传页面。
- 项目新增 `langchain-tavily`、`TAVILYSEARCH_API_KEY`（兼容 `TAVILY_API_KEY`） 和有限超时、重试、并发与熔断配置。系统不新增自主 Agent、独立网页正文抓取、向量库或跨请求资料缓存。
