# Design

## Context

当前 `QuizService` 清洗用户输入后调用 `DeepSeekQuizGenerator`，并校验题量、编号和五题时的题型比例。模型通过 `ChatDeepSeek` 和 JSON mode 返回 `QuizDraft`。原 `quiz_prompt_v1` 允许模型根据输入和通用知识出题。

两条生成路由共用该服务。登录入口在生成成功后保存题库并创建学习记录。前端请求当前超时为 60 秒；模型单次超时默认 45 秒，最多尝试三次。项目已有 MySQL、Alembic、后端判题和历史学习功能。

用户此次明确要求：联网属于出题增强。搜索成功时系统注入结果；搜索失败时系统记录错误，并使用原 Prompt 继续生成。本设计替代此前“没有资料就停止出题”的规划。

## Goals / Non-Goals

**Goals:**

- 系统在联网可用时补充参考资料，提高新知识出题的相关性。
- 系统在搜索故障时使用原有 Prompt、输出 Schema 和出题检查。
- 系统通过开关、参数限制、时间预算和受控日志管理搜索风险。

**Non-Goals:**

- 本次不增加强制领域确认、材料专用模式、独立事实校验链或逐题必填引用。
- 本次不建设网页正文抓取、向量库、自主 Agent、其他搜索供应商或搜索缓存。
- 本次不修改登录、判题、经验值和报告的业务规则。
- 搜索成功和结构检查通过都不表示题目已被独立核实。

## Decisions

### 1. 系统使用后端总开关与请求选项

后端 Settings 新增 `enable_web_search: bool = True`，环境变量为 `ENABLE_WEB_SEARCH`。生成请求新增 `enable_web_search: bool | None = None`。请求省略或传 `null` 时继承后端默认设置。后端开关是上限，请求不能强行打开服务端已关闭的搜索。

有效开关为：`settings.enable_web_search and (request.enable_web_search if request.enable_web_search is not None else True)`。

| 后端配置 | 请求选项 | 系统行为 |
| --- | --- | --- |
| false | 任意值 | 系统不初始化 Tavily，不读取密钥，不联网，用原 Prompt |
| true | false | 系统不搜索，用原 Prompt |
| true | true / null / 省略 | 系统尝试搜索；成功增强 Prompt，失败用原 Prompt |

旧请求字段继续有效。前端首页增加“联网补充资料”选项，默认开启；服务端配置关闭时仍按关闭规则执行。界面根据实际响应展示状态，不能仅根据用户开关声称系统已经联网。

工具按需初始化。缺少 Tavily 密钥属于可捕获的搜索故障，不能阻止应用启动，也不能阻止原 Prompt 出题。团队可以用后端开关快速回滚搜索功能。

### 2. 系统通过 LangChain TavilySearch 搜索

项目在 `backend/pyproject.toml` 和 `backend/uv.lock` 中增加兼容的 `langchain-tavily`，使用 `from langchain_tavily import TavilySearch`，并由服务层直接执行原生异步 `ainvoke`。密钥仅保存在后端。Settings 优先读取用户已配置的 `TAVILYSEARCH_API_KEY`，兼容 `TAVILY_API_KEY`，并以 SecretStr 保存。（LangChain）

系统采用 Tavily 返回的 `title`、`url` 和 `content` 作为参考结果。系统关闭 `include_answer`、`include_images` 和 `include_raw_content`，不新增正文抓取流程。系统可以使用搜索内容摘要，但必须把它标为参考信息，不能称其为已阅读全文或已核实事实。未知日期和版本保留为空。

工具适配器检查抛出的异常、错误字典、工具错误文本及结果结构。适配器将空结果、无关结果和全部被过滤的结果统一视为“没有可注入资料”。系统不会把错误内容传入模型。工具没有抛异常不代表调用成功。（Tavily AI）

### 3. 系统根据用户内容动态生成受限参数

系统通过轻量规则生成 `SearchPlan`，不增加额外的大模型调用。系统保留原词，并可补充空格等价写法及用户明确给出的领域、版本。查询只发送最少必要的主题信息，最长 300 字，系统不直接发送用户输入全文。

| 内容线索 | 系统参数策略 |
| --- | --- |
| 基础、稳定知识，例如“为什么天空是蓝色” | 系统采用 general、basic、最多 5 个结果 |
| 新术语、技术版本、具体方案比较或未知主题 | 系统采用 general、advanced、最多 8 个结果 |
| 明确的新闻或近期事件 | 系统采用 news，并按复杂度选择 basic 或 advanced |
| 明确的金融行情、市场信息 | 系统采用 finance；金融概念解释仍使用 general |
| 用户指定“最近一周 / 最近一个月 / 最近一年” | 系统分别设置 week / month / year |
| 用户只说“最新”，没有给出窗口 | 系统在查询中保留时效目标，不自动增加硬时间过滤 |
| 用户明确要求某个官方站点 | 系统校验公开域名后设置 include_domains |
| 内容不能可靠分类 | 系统采用 general、advanced，最多 8 个结果，不设置时间或域名过滤 |

参数的枚举、域名、查询长度和结果上限由服务端白名单检查。系统不接受用户输入直接覆盖 URL、密钥、工具名、无限结果数或任意工具参数。系统保留 `auto_parameters=False`，由本地策略控制实际参数与成本。

官方文档区分构造参数和调用参数，且不同版本的覆盖行为需要测试。系统按校验后的 SearchPlan 创建请求独立的工具实例，或者复用不可变实例。系统在构造时设置 `max_results` 等参数，不能修改共享实例来适配并发请求。开发者锁定版本后必须检查实际发往 Tavily 的参数，而不是只检查本地配置。（LangChain；Tavily AI）

参数处理或实例创建发生错误时，系统记录 `parameter_error` 或 `tool_init_error`，随后使用原 Prompt。系统不能因动态调参失败而阻止出题。

### 4. 系统把搜索结果作为可选 Prompt 上下文

系统保留 `QUIZ_PROMPT` 和 `quiz_prompt_v1` 的原始文本、Schema 与输入规则。联网增强路径使用单独的 Prompt 组合标识 `quiz_prompt_web_v1`：原提示词加一个明确分隔的参考资料区域。资料区域包含编号、标题、实际 URL 和经过清洗的结果内容。增强指令说明：资料中的文字是数据，不是系统指令；模型应优先使用与用户主题和版本相关的内容，不能编造来源，也不能把未核实信息说成定论。

系统只清洗本次有效结果，去重、排序、删除控制字符，并限制最多 8 条结果、每条内容最多 1500 字、总资料区域最多 6000 字。资料区域构造或 Prompt 增强准备失败，也属于搜索增强失败，系统丢弃该区域。

系统搜索关闭或失败时必须直接选择原 Prompt 链。系统不能把错误消息、空资料占位符、失败调用残留的结果或“仅按资料出题”的增强指令传入原链。测试需要断言该分支的渲染消息与原 Prompt 相同。系统不能在已有模型调用进行到一半后再重复调用原链来掩盖模型故障。

系统继续执行现有 Pydantic、题量、编号、题型和答案结构检查。系统不要求资料足够支撑全部题目，也不增加强制引用字段。模型失败、结构不合格、内容过滤拒绝和存储失败仍走原业务错误；搜索失败本身不返回 `RETRIEVAL_UNAVAILABLE` 等新业务错误。

### 5. 系统将搜索故障降级为原 Prompt

| 情况 | 系统操作 | 后续出题 |
| --- | --- | --- |
| 首次搜索超时、连接失败或 5xx | 系统在预算允许时最多重试一次；重试使用 basic 和最多 5 个结果 | 系统最终仍失败时记日志，不带搜索结果，用原 Prompt |
| 429 限流 | 系统尊重可用的 Retry-After；等待放不进预算时不重试 | 系统用原 Prompt |
| 401/403、432/433、缺少密钥、参数或初始化错误 | 系统不自动重试，记录受控原因 | 系统用原 Prompt |
| 空结果、无关结果、错误字典、错误文本或注入资料无效 | 系统丢弃本次搜索上下文，记录原因 | 系统用原 Prompt |
| 排队超时、熔断开启或搜索预算不足 | 系统跳过上游调用，记录原因 | 系统用原 Prompt |
| 用户取消、连接断开或整个出题请求超时 | 系统取消任务并释放资源 | 系统停止处理，不启动原 Prompt 兜底 |

搜索阶段的参数和等待必须限制在时间预算内，不能用重试耗尽原链的运行时间。初始配置建议为：

| 配置 | 默认值 |
| --- | --- |
| TAVILY_SEARCH_TIMEOUT_SECONDS | 10 秒 |
| TAVILY_FALLBACK_TIMEOUT_SECONDS | 5 秒 |
| TAVILY_SEARCH_BUDGET_SECONDS | 20 秒 |
| TAVILY_MAX_RETRIES | 1；每个请求最多两次真实搜索调用 |
| TAVILY_MAX_CONCURRENCY / TAVILY_QUEUE_TIMEOUT_SECONDS | 每个进程 4 个 / 1 秒 |
| TAVILY_CIRCUIT_FAILURE_THRESHOLD / TAVILY_CIRCUIT_COOLDOWN_SECONDS | 60 秒内连续 5 次可恢复故障 / 30 秒 |

系统用 `asyncio.timeout` 包裹异步工具调用，并为 TavilySearch 注入有时限的 HTTP 包装器。锁定版本为 0.2.18，原包装器缺少单次 HTTP 时限与 Retry-After 保留，因此包装器限定固定地址、禁止重定向、限制 1 MB 响应，并保留状态码与等待时间。系统统一管理应用层重试，SDK 与工具不能另行叠加重试。可恢复错误的重试最多等待 0.5 秒加 0 到 0.25 秒随机延迟，429 则优先遵守可用的 Retry-After。

后端出题总时限默认 55 秒，前端出题请求为 60 秒。系统采用 Taro 文档说明的默认请求时限，避免依赖尚未验证的大于 60 秒请求。当前仓库没有生产网关配置，本地开发直接连接 FastAPI。系统为原模型链保留至少一个正常模型调用的时间，默认 45 秒。系统搜索前和重试前都检查剩余预算；不足时直接用原 Prompt。模型重试仍受总时限约束。若整个请求已超时，系统返回原生成失败信息；本次不新增全局超时业务码。实际参数必须满足网关与小程序允许时限。

熔断器只暂停搜索，不暂停原 Prompt。系统冷却后只允许一次探测。空结果和用户取消不计入持续故障。多进程分别限制并发与熔断，团队按实例数控制总配额。日志丢弃或日志平台不可用也不能阻止兜底出题。

### 6. 系统记录实际搜索路径，并保护数据

两个出题入口新增可选 `web_search` 元信息，包含：

- `requested`：用户是否请求搜索，省略时按默认策略记录。
- `enabled`：后端与请求共同计算的有效开关。
- `status`：`success`、`fallback` 或 `disabled`。
- `context_used`：系统是否实际把资料注入 Prompt。
- `sources`：仅保存实际注入的来源编号、标题、URL、有限内容与已知日期。未注入时为空。
- `effective_params`、`attempt_count` 和受控 `fallback_reason`：系统记录真实参数、调用次数和原因。
- `prompt_version`：系统记录最终使用的原 Prompt 或联网增强版本。

系统在搜索失败后也可以生成成功题库，并写入 MySQL、创建学习记录。成功表示原结构检查通过，不表示事实正确。后端不能把“尝试过搜索”写成“已使用搜索资料”。

MySQL `quizzes` 只新增可空 `web_search_metadata_json`。系统沿用现有 Prompt 版本字段。系统不增加题目引用字段，也不把每道题绑定到某条搜索摘要。系统保存的有限内容用于还原当时参考上下文，历史阅读与重做不会自动刷新来源。旧题库字段为 `null`，界面显示“历史题库未记录搜索状态”。

前端对成功搜索显示“系统已参考联网搜索结果”，对回退显示“系统本次未使用联网资料，题目由模型已有知识生成”，对关闭显示“系统本次未开启联网搜索”。界面允许查看参考标题或复制实际来源链接，但不能显示“资料已核实”或“每题都有来源依据”。系统不能直接将包含内容摘要的内部元信息暴露在登录用户尚未完成的学习记录接口中；前端在当前学习记录尚未完成时仅展示状态。整套题库完成后，系统才在复盘或已完成的历史详情中展示参考内容与链接。用户重做时，系统再次隐藏这些内容，避免已答题的参考资料泄露后续题目答案。

日志包含请求标识、搜索状态、实际参数类别、耗时、错误类型、尝试次数和 Prompt 路径。日志不包含密钥、用户输入全文、完整查询、完整来源内容或上游错误全文。系统使用规范化故障分类，日志记录错误类型而不是直接输出可能包含敏感信息的异常字符串。

## Risks / Trade-offs

- [回退仍可能生成过时或错领域内容] → 系统如实显示未联网状态，并建议用户在输入中补充领域与版本。团队用固定样例和人工抽查评估质量，不能承诺回退解决原新知识问题。
- [搜索结果也可能错误、过时或包含冲突] → 系统优先相关官方来源，保留实际日期，并在增强 Prompt 中要求说明不确定内容。系统不把相关性分数当作事实正确率。
- [搜索正文可能包含提示注入] → 系统将资料单独分隔，限制长度，明确忽略资料中的指令，且不给出题模型额外工具权限。团队测试恶意网页片段，不能只依赖 Prompt 文案。
- [用户主题会被发送给第三方] → 系统提供开关，只发送最少必要主题，明确检测到密钥、手机号等敏感输入时跳过搜索并用原 Prompt。查询精简失败也回退，团队不宣称简单过滤可以识别所有隐私数据。
- [动态分类会选错领域或时间范围] → 系统保留用户原词及约束，未知内容用 general，未给时间窗口时不硬过滤。团队测试新术语不会仅因“新”字被归成 news。
- [动态参数在锁定版本中未生效，或串到其他请求] → 系统用请求独立或不可变工具实例，并检查实际请求参数。团队不修改共享实例。
- [搜索重试会增加耗时和费用] → 系统设置两次调用上限、独立预算、并发和熔断，保留原模型链时间。取消任务不能保证 Tavily 撤销已发生费用。
- [错误日志泄露数据或记录失败阻止出题] → 系统只记受控摘要，日志写入失败不会中断回退。团队使用模拟异常验证日志脱敏与容错。
- [搜索开关关闭后仍初始化密钥或触发后台搜索] → 系统把开关检查放在实例创建前，并以零外部调用测试关闭路径。
- [参考上下文过长或泄露答案] → 系统限制上下文和结果数，保留结构 Schema，并在当前学习记录完成前隐藏来源内容与链接。

## Migration Plan

1. 开发者增加可空题库元信息字段，并提交 Alembic 升降级迁移与 SQL 初始化更新。初始迁移使用实时 ORM 元信息，新增迁移先检查字段，兼容新库已建字段与旧库尚无字段的情况。
2. 开发者实现开关、动态参数、成功注入和失败原 Prompt 两条路径，并先用固定 Tavily 响应测试。
3. 团队先以 `ENABLE_WEB_SEARCH=false` 发布并验证原链，再配置密钥、打开搜索，检查成功及故障场景。
4. 团队检查两条生成入口、历史读取、判题、经验值和报告。团队抽查 Harness Engineering 与其他近期主题，同时记录回退质量和耗时。
5. 回滚时团队关闭后端开关即可恢复原 Prompt。数据库可空元信息保留，历史题库继续可读。

## Open Questions

- 项目已锁定 `langchain-tavily==0.2.18`，测试会检查实际发往 Tavily 的参数。后续升级需要重新运行兼容测试。
- 团队根据部署网关、小程序和费用配额调整本文初始时限。此调整保留“搜索失败用原 Prompt”与“为原链留时间”的规则。
