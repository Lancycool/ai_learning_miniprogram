# private-knowledge-bases Specification

## Purpose

系统让用户保存自己的文档与文字，并按文档和章节组织学习资料。系统提供可恢复的处理任务、私有访问检查和持久化索引，让用户在重新打开小程序或后端重启后仍可以继续使用已完成的资料。

## Requirements

### Requirement: 用户可以管理自己的知识库
系统 MUST 允许登录用户新建、查看、修改和删除个人知识库。系统 MUST 在列表、详情、修改、任务、章节、题库和检索的每次访问中检查资源归属。系统 MUST 对他人的资源与不存在的资源返回相同的不存在结果。

#### Scenario: 用户管理自己的资料
- **WHEN** 登录用户新建知识库并再次进入小程序
- **THEN** 系统显示该用户保存的知识库与文档状态
- **AND** 系统不展示其他用户的资源

#### Scenario: 用户猜到他人的资源编号
- **WHEN** 用户使用他人的知识库、文档、章节或任务编号访问接口
- **THEN** 系统返回资源不存在，并且不读取或返回该资源的内容

### Requirement: 系统支持指定文件和文字输入
系统 MUST 支持带可提取文字的 PDF、DOCX、Markdown、TXT，以及用户主动保存的文字资料。系统 MUST 拒绝超过 30 MB 的文件、空文件、格式伪装和不支持的文件。系统 MUST 清楚提示扫描件、加密文件和当前无法读取的内容，不能静默丢失内容并标记成功。

#### Scenario: 用户上传有效文件
- **WHEN** 用户上传符合类型与大小要求的文件
- **THEN** 系统保存私有文件与文档记录，并返回处理任务

#### Scenario: 用户提交不支持的资料
- **WHEN** 用户上传 PPT、旧版 DOC、视频或没有可提取文字的扫描 PDF
- **THEN** 系统提示当前不支持，并说明用户可以上传支持的文件或粘贴文字

#### Scenario: 用户保存一段文字
- **WHEN** 用户在知识库中填写资料标题与有效文字
- **THEN** 系统把这段文字保存为独立资料，并提供相同的预览、章节和处理状态

### Requirement: 文档处理使用可恢复的后台任务
系统 MUST 在文件接收与保存完成后返回任务编号和状态，解析与建索引 MUST 在后台执行。任务 MUST 区分排队、运行、成功和失败，并显示实际处理阶段。前端 MUST 默认每五秒查询一次，且不同时发出重复查询。系统 MUST 保证相同提交不重复创建文档或任务。

#### Scenario: 用户离开处理页面
- **WHEN** 用户已提交文件，随后离开页面或关闭小程序
- **THEN** 后台继续执行已经接收的任务
- **AND** 用户重新打开文档列表时可以恢复查看任务

#### Scenario: 上传响应丢失
- **WHEN** 文件已保存，但客户端未收到响应并使用原请求编号重试
- **THEN** 系统返回原文档与任务，不重复占用存储空间或建索引

#### Scenario: 后端在处理中重启
- **WHEN** 任务已经运行但后端意外退出
- **THEN** 系统在运行期限结束后显示可重试的中断状态
- **AND** 系统不发布未完成索引，排队任务可以继续被处理

### Requirement: 用户可以预览并选择章节
系统 MUST 返回从文档文字和结构识别的章节、章节层级和文字预览。系统 MUST 保留没有归入明确章节的内容，并允许用户选择整篇文档或具体章节。系统 MUST 不提供页码选择，不编造无法确认的章节。用户修改章节归属后，系统 MUST 使用对应版本的章节范围。

#### Scenario: 文档有明确章节
- **WHEN** 系统处理包含章节标题的文档
- **THEN** 用户可以预览并勾选章节，再把选择用于出题或原题练习

#### Scenario: 文档没有明确章节
- **WHEN** 系统无法可靠识别章节边界
- **THEN** 系统显示未分章内容和识别提示，并允许用户使用全文
- **AND** 系统不把虚构章节当作文档原结构

#### Scenario: 章节编号不属于所选文档
- **WHEN** 用户提交不属于当前用户或所选文档版本的章节编号
- **THEN** 系统拒绝请求，且不扩大为全文检索

### Requirement: 系统只发布完整且可用的索引
系统 MUST 在全部必要文本片段保存完成后才标记索引可用。系统 MUST 保留文档和索引版本，并拒绝把不同向量配置混用。系统 MUST 在超时、配额错误、存储错误或取消后保留受控失败原因与重试入口。成功解析的文字 MUST 可以独立预览和用于原题导入。

#### Scenario: 向量服务在中途失败
- **WHEN** 文档已解析，但部分片段尚未完成向量化
- **THEN** 文档显示索引失败，并且不能用于知识库出题
- **AND** 用户仍可以预览已经完整解析的文字，或基于它审核原题

#### Scenario: 用户重试失败索引
- **WHEN** 用户对失败任务发起重试
- **THEN** 系统创建受限的新处理版本，并避免重复片段与失效版本进入检索

#### Scenario: 系统重启后读取已完成索引
- **WHEN** 后端正常重启且持久化目录仍在
- **THEN** 用户可以继续检索此前完成的文档，不需要重新上传

### Requirement: 删除资料停止后续检索
系统 MUST 在用户删除文档或知识库后立即禁止新的检索、原题练习和迟到任务发布。系统 MUST 清理原文件、解析文件与向量，清理失败时 MUST 提供受控状态并继续重试。系统 MUST 保留已生成或已经进入学习记录的题目、引用快照与成绩，并在删除说明中告知用户。

#### Scenario: 用户删除仍在处理的文档
- **WHEN** 用户删除文档后，原处理任务仍返回结果
- **THEN** 系统不发布该结果，并清理它产生的文件与向量

#### Scenario: 用户查看已删除资料的旧学习记录
- **WHEN** 用户打开资料删除前已保存的学习记录
- **THEN** 系统保留原题、引用快照和成绩，并标明原资料已经删除

### Requirement: 私有文件不通过公开地址读取
系统 MUST 把原文、解析文本与索引保存在非公开目录。系统 MUST 对预览或下载执行登录与归属检查。系统 MUST 不在普通日志、错误响应或客户端缓存中保存密钥、完整资料正文、内部路径或上游错误全文。用户退出登录后，前端 MUST 清理或隔离该用户的私人页面状态。

#### Scenario: 未登录用户尝试读取资料
- **WHEN** 未登录用户请求资料预览或原文件
- **THEN** 系统拒绝访问，并且没有公开静态地址可以绕过检查

#### Scenario: 服务错误包含密钥和资料正文
- **WHEN** 解析、向量或数据库操作抛出包含敏感内容的错误
- **THEN** 系统只记录任务编号、阶段和受控错误类型，并返回可理解的提示

### Requirement: 新功能故障不阻止现有学习
系统 MUST 提供知识库功能开关。功能关闭、配置缺失或新依赖不可用时，系统 MUST 保持普通出题、登录、答题、历史、错题和报告可用。系统 MUST 在知识库入口显示受控的不可用状态，不伪造处理成功。

#### Scenario: 向量服务配置缺失
- **WHEN** 百炼配置缺失，但用户使用普通主题生成题目
- **THEN** 系统按现有普通出题规则执行
- **AND** 知识库处理入口给出服务暂不可用的提示
